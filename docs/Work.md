# 小组分工

## 当前任务目标

项目代码结构已经基本完成，现在主要任务是围绕现有代码完成数据、训练、系统展示和报告。

当前已有内容：

- PINN 训练脚本：`train/train_pinn.py`
- PINN 模型定义：`backend/models/pinn_model.py`
- 模型权重目录：`backend/models/weights/`
- 后端模型推理：`backend/logic/pinn_inference.py`
- 后端预测接口：`POST /api/predict_typhoon`
- 前端预测轨迹和指标展示

接下来小组分为两组：

- 两个人负责数据集和训练集。
- 两个人负责后端模型调用、前端页面调整和报告整合。

## 成员 A、B：数据集查找、整理与数据处理

负责内容：

- 详细阅读训练模块的代码，以及接入后端的参数

- 根据项目代码需要查找合适的台风历史路径数据集。
- 对比数据集来源、字段完整性、时间范围和可用性。
- 确定最终使用的数据集。
- 整理数据字段说明，例如台风编号、时间、经度、纬度、风速、气压。
- 根据训练代码要求整理数据格式。
- 清洗缺失值、异常值和重复数据。
- 统一时间格式和时间间隔。
- 将数据整理为 `.csv`、`.json` 或 `.jsonl`。
- 划分训练集和测试集。
- 准备带真实未来轨迹的测试样本。

报告负责部分：

- 数据集来源。
- 数据集字段说明。
- 为什么该数据集适合本项目。
- 数据在 AI4S 台风预测任务中的作用。

- 数据预处理方法。
- 训练集和测试集构建。
- 缺失值、异常值和时间对齐处理。
- 数据质量对模型结果的影响。

## 成员 C、D：后端模型调用与实验结果、前端页面与报告整合

负责内容：

- 使用整理好的训练集训练 PINN 模型。
- 生成模型权重文件：

```text
backend/models/weights/typhoon_pinn_v1.pth
```

- 检查后端是否能正确加载模型。
- 调用 `/api/predict_typhoon` 测试预测结果。
- 对比 PINN 预测轨迹和 baseline 预测轨迹。
- 整理接口返回的 `losses` 和 `metrics`。
- 检查前端页面是否正常展示预测结果。
- 根据需要调整前端展示内容。
- 确保页面能清楚展示 PINN 轨迹、baseline 轨迹和真实轨迹。
- 展示 data loss、physics loss、轨迹误差等指标。
- 截取系统运行效果图。
- 整合最终报告和答辩材料。

报告负责部分：

- 模型调用流程。
- PINN 与 baseline 对比实验。
- 轨迹误差、终点误差、风速误差、气压误差。
- 实验结果分析。

- 系统实现说明。
- 前端可视化展示。
- 项目总结。
- 项目不足与改进方向。
- 最终报告排版和内容统一。
