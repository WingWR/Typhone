# TyphoonAI：基于 PINN 的台风轨迹预测研究报告

## 1. 引言

AI for Science 强调用人工智能方法辅助科学建模。台风轨迹预测具有明确的历史观测数据，同时又受到地球自转、移动惯性、海陆分布和强度变化等因素影响，因此适合作为数据驱动模型与物理先验结合的课程项目。

本项目 TyphoonAI 构建了一个基于 Physics-Informed Neural Network（PINN）的台风轨迹预测与可视化系统。系统输入为台风近期观测序列，包括相对时间、经度、纬度、最大风速和中心气压；系统输出为未来若干步的台风中心位置、风速、气压以及局部速度分量。与普通回归模型相比，本项目在训练中加入速度、惯性、科里奥利力、风速-气压关系和近岸衰减等约束，使模型不仅拟合观测数据，也尽量减少不合理的轨迹跳变和强度变化。

本项目的主要工作包括三部分：第一，整理并合并 2016-2025 年的 CHBST 台风路径数据，完成清洗、归一化、序列样本构造以及按台风编号划分训练/验证/测试集；第二，实现 4 层 MLP 形式的 PINN 模型，并设计包含数据拟合和物理约束的损失函数；第三，将训练好的 `typhoon_pinn_v2.pth` 接入 Flask 后端和 React/DeckGL 前端，支持上传台风观测 JSON、调用 PINN 预测、与线性平滑基线对比，并在地图上展示轨迹。

## 2. 数据集与数据处理

### 2.1 数据来源

当前终版项目使用的数据为 `train/dataset/` 目录下 2016-2025 年共 10 个 CHBST 台风最佳路径 CSV 文件。

| 数据文件 | 行数 |
|---|---:|
| `CH2016BST_pinn_dataset.csv` | 725 |
| `CH2017BST_pinn_dataset.csv` | 827 |
| `CH2018BST_pinn_dataset.csv` | 1251 |
| `CH2019BST_pinn_dataset.csv` | 1003 |
| `CH2020BST_pinn_dataset.csv` | 733 |
| `CH2021BST_pinn_dataset.csv` | 926 |
| `CH2022BST_pinn_dataset.csv` | 741 |
| `CH2023BST_pinn_dataset.csv` | 789 |
| `CH2024BST_pinn_dataset.csv` | 877 |
| `CH2025BST_pinn_dataset.csv` | 999 |

合并后的数据共包含 287 个台风、8871 个观测点。每个台风最少 7 个观测点，最多 91 个观测点，平均 30.91 个观测点。时间间隔主要为 3 小时和 6 小时，其中 3 小时间隔出现 1413 次，6 小时间隔出现 7171 次，因此训练时不能把所有相邻点都简单看作固定步长。

| 字段 | 最小值 | 最大值 | 含义 |
|---|---:|---:|---|
| `t_hours` | 0.0 | 510.0 | 距该台风首个观测点的小时数 |
| `lng` | 97.8 | 255.0 | 台风中心经度 |
| `lat` | 3.4 | 70.1 | 台风中心纬度 |
| `wind_speed` | 10.0 | 75.0 | 最大风速，单位 m/s |
| `pressure` | 890.0 | 1014.0 | 中心气压，单位 hPa |

### 2.2 数据预处理流程

数据预处理主要由 `train/train_pinn.py` 完成。终版训练脚本支持读取单个 CSV/JSON/JSONL 文件，也支持传入目录并自动合并目录下所有受支持的数据文件。

| 环节 | 处理方式 |
|---|---|
| 数据读取 | CSV 使用 `utf-8-sig` 编码读取，能够处理带 UTF-8 BOM 的表头；目录模式下按文件名排序后逐个读取并合并。 |
| 字段检查 | 训练数据必须包含 `storm_id`、`lng`、`lat`、`wind_speed`、`pressure`，并且必须包含 `t_hours` 或 `timestamp` 之一。 |
| 时间处理 | 如果只有 `timestamp`，脚本会按 `storm_id` 分组，将每个观测点转换为相对于该台风首个观测点的 `t_hours`。 |
| 数值清洗 | 将 `t_hours`、经纬度、风速和气压转为数值类型，无法转换的值会变为缺失值并被删除。 |
| 冗余字段处理 | 如果存在 `source_file`、`storm_name` 等非训练字段，预处理阶段会删除，避免进入模型特征。 |
| 排序去重 | 按 `storm_id` 和 `t_hours` 去重，同一台风同一时刻只保留最后一条记录，再按台风编号和时间升序排序。 |
| 归一化 | 使用 `TensorScaler` 对 `t_hours`、`lng`、`lat`、`wind_speed`、`pressure` 做 min-max 归一化，映射到 `[-1, 1]`。缩放器只在训练集上拟合。 |

这种处理方式有两个重点。第一，目录合并使训练数据覆盖 10 个年份，显著增加了样本覆盖范围。第二，归一化只使用训练集统计量，再应用到验证集和测试集，避免验证或测试数据的信息泄漏到训练过程。

### 2.3 序列样本构造

模型输入不是单个观测点，而是长度为 4 的历史窗口。每个观测点包含 5 个特征，因此输入维度为：

```text
4 * 5 = 20
```

对于长度为 `N` 的台风轨迹，脚本会构造 `N - 4` 个监督学习样本。每个样本以前 4 个观测点作为输入，以第 5 个观测点的状态作为预测目标：

```text
(lng, lat, wind_speed, pressure)
```

`TyphoonSequenceDataset` 除了保存归一化后的输入窗口和目标状态，还保存未归一化的目标状态、上一时刻状态、上上时刻状态、当前时间间隔 `dt_hours` 和上一段时间间隔 `previous_dt_hours`。这些原始量不直接输入神经网络，但会参与速度、加速度、科里奥利残差等物理损失计算。这样既能保持模型输入简单，又能保证物理约束在真实单位下计算。

### 2.4 训练/验证/测试划分

终版训练采用按台风编号划分数据集，而不是随机打乱滑动窗口样本。这样可以避免同一条台风轨迹中高度相似的相邻窗口同时出现在训练集和验证集里。

训练脚本先使用 `test_ratio=0.1` 从 287 个台风中划出测试集，再在剩余台风中使用 `val_ratio=0.2` 划出验证集。随机种子为 42。最终划分如下：

| 集合 | 台风数 | 原始观测点 | 序列样本数 |
|---|---:|---:|---:|
| 训练集 | 206 | 6520 | 5696 |
| 验证集 | 52 | 1484 | 1276 |
| 测试集 | 29 | 867 | 751 |

从数据质量看，当前数据覆盖年份更长，台风数量更多，能够比单年数据更好地覆盖不同路径和强度变化。但数据仍然主要来自最佳路径记录，只有位置、风速和气压等低维变量，没有海温、环境风场、湿度场等空间气象场信息。因此本项目更接近“基于历史轨迹和强度序列的短期预测”，不能等同于完整的数值天气预报。

## 3. 方法

### 3.1 模型架构

模型定义在 `backend/models/pinn_model.py` 中，核心类为 `TyphoonPINN`。模型是 4 层全连接 MLP，包括 3 个隐藏线性层和 1 个输出层，隐藏层维度为 128，激活函数为 `Tanh`。输入维度为 20，输出维度为 6。

| 输出变量 | 含义 |
|---|---|
| `lng` | 下一时刻台风中心经度 |
| `lat` | 下一时刻台风中心纬度 |
| `wind_speed` | 下一时刻最大风速 |
| `pressure` | 下一时刻中心气压 |
| `u_mps` | 东西向速度分量，单位 m/s |
| `v_mps` | 南北向速度分量，单位 m/s |

模型输出经过范围约束。前 4 个状态变量通过 `tanh` 限制在 `[-1, 1]`，对应归一化后的状态空间；后 2 个速度分量通过 `80.0 * tanh(...)` 限制在约 `[-80, 80] m/s`。这种设计可以减少推理时出现极端位置、风速或速度值的风险。

### 3.2 损失函数设计

终版代码中的损失函数为 `PINNLoss`。它由数据拟合项和五类物理/运动约束组成，其中速度类约束在实现上拆成了“速度一致性”和“速度监督”两个损失项。因此总损失包含 1 个数据项和 6 个约束项：

```text
L_total = L_data
        + 1e-3 * L_velocity_consistency
        + 1e-3 * L_velocity_supervised
        + 1e4 * L_inertia
        + 1e4 * L_coriolis
        + 0.05 * L_wind_pressure
        + 0.02 * L_nearshore
```

| 损失项 | 作用 |
|---|---|
| 数据拟合损失 | 预测的归一化状态与真实下一时刻状态之间的均方误差，是主要监督信号。 |
| 速度一致性损失 | 将模型输出速度与“上一位置到预测位置”计算得到的速度对齐，约束离散形式的 `dx/dt = v`。 |
| 速度监督损失 | 将模型输出速度与“上一位置到真实目标位置”计算得到的真实速度对齐，使速度分量更稳定。 |
| 惯性约束损失 | 使用预测速度与上一段速度计算加速度，惩罚过大的瞬时加速度，减少轨迹急转和振荡。 |
| 科里奥利力损失 | 使用 `f = 2 * Omega * sin(lat)` 构造弱残差，体现旋转地球背景下的大尺度运动约束。 |
| 风速-气压耦合损失 | 台风增强时通常风速增大、中心气压降低；代码惩罚风速趋势和气压趋势同向变化的情况。 |
| 近岸衰减损失 | 使用简化海岸线函数估计近岸位置，惩罚近岸后继续增强的风速或继续下降的气压。 |

近岸衰减使用的简化海岸线函数为：

```text
coast_lng = 120.35 + 0.19 * (lat - 26.0) + 0.08 * sin((lat - 26.0) * 1.6)
```

这些约束不是完整的大气动力学方程，而是适合课程项目规模的弱物理先验。它们的主要价值是让模型在小样本和低维输入条件下，避免明显不合理的运动和强度变化。

### 3.3 训练配置

终版训练结果来自 `backend/models/weights/typhoon_pinn_v2.summary.json`。训练使用 CPU、Adam 优化器、学习率 0.001、batch size 32、随机种子 42、梯度裁剪阈值 1.0。最大训练轮数为 300，早停 patience 为 50，`min_delta=0.0001`。监控指标为验证集总损失 `val_loss`。

| 参数 | 数值 |
|---|---:|
| 输入序列长度 | 4 |
| 输入维度 | 20 |
| 隐藏层维度 | 128 |
| 输出维度 | 6 |
| 最大轮数 | 300 |
| 实际完成轮数 | 217 |
| 最佳轮数 | 167 |
| 最佳验证损失 | 0.01022890 |
| 训练样本数 | 5696 |
| 验证样本数 | 1276 |
| 测试样本数 | 751 |

### 3.4 推理机制

推理逻辑位于 `backend/logic/pinn_inference.py`。后端默认加载 `backend/models/weights/typhoon_pinn_v2.pth`。前端上传 JSON 后，后端解析 `storm_id`、`storm_name`、`basin`、`forecast_steps`、`time_step_hours` 和 `observations` 等字段。`forecast_steps` 被限制在 1-24 步，`time_step_hours` 被限制在 1-6 小时。

PINN 推理采用自回归方式：系统取最近 4 个观测点作为输入；如果观测点不足 4 个，就用最早观测点补齐。模型预测下一步后，将预测点追加到历史序列中，再继续预测后续步。为了便于对比，后端同时计算线性平滑基线。该基线使用最近最多 5 个观测点估计经度、纬度、风速和气压的变化率，并使用 `0.92^(step-1)` 作为逐步衰减系数。

如果上传数据包含 `actual_track`，后端会计算 PINN 轨迹误差、最终位置误差、风速 MAE、气压 MAE，以及线性平滑基线对应的误差。项目中的 `backend/data/real_typhoon_muifa_2022.json`、`real_typhoon_hinnamnor_2022.json` 和 `real_typhoon_doksuri_2023.json` 就是带有真实未来轨迹的示例输入。

## 4. 系统架构

本系统采用三层结构：训练层、后端服务层和前端可视化层。

训练层使用 PyTorch，主要文件为 `train/train_pinn.py` 和 `backend/models/pinn_model.py`。训练脚本负责目录数据合并、预处理、按台风编号划分训练/验证/测试集、构造序列样本、训练 PINN、执行早停，并保存 `typhoon_pinn_v2.pth` 和 `typhoon_pinn_v2.summary.json`。

后端服务层使用 Flask，入口为 `backend/app.py`，路由位于 `backend/api/routes.py`。主要接口包括 `GET /api/health`、`POST /api/predict_typhoon` 和 `GET /api/get_weather_conditions`。其中 `/api/predict_typhoon` 是核心预测接口，返回观测轨迹、PINN 预测轨迹、线性平滑基线轨迹、物理损失分解、指标摘要和天气图层上下文。

前端可视化层使用 React 19、DeckGL 9、MUI 7 和 Vite。`MapScene.jsx` 负责地图和轨迹图层，`ForecastSidebar.jsx` 负责上传 JSON 与展示观测信息，`MapLegend.jsx` 展示 PINN、Baseline、Actual 三类轨迹图例，`TimelineBar.jsx` 负责时间轴回放。

系统数据流如下：

```text
台风观测 JSON
    -> React 前端上传
    -> Flask /api/predict_typhoon
    -> PINN 推理与线性平滑基线计算
    -> 返回轨迹、损失、指标和天气上下文
    -> DeckGL 地图和侧栏展示
```

## 5. 实验结果与分析

### 5.1 训练过程

![模型训练过程](assets/training_process.svg)

训练曲线显示，模型在前期快速收敛。第 1 轮训练损失为 1.67850671，验证损失为 0.29562713；到第 5 轮，训练损失下降到 0.12198998，验证损失下降到 0.10129702；第 50 轮验证损失进一步下降到 0.01911666。最佳验证损失出现在第 167 轮，为 0.01022890。之后验证损失没有持续突破早停阈值，训练在第 217 轮停止。

与早期单年训练相比，v2 的训练数据量明显增大，验证损失和测试集位置误差都更加可报告。测试集平均位置误差约 56.45 km，说明模型在未见过的台风编号上仍具备一定短期预测能力。

### 5.2 物理一致性分析

最佳轮验证集上，数据拟合损失为 0.00243342，说明模型在归一化状态空间中已经能够较好拟合下一步经度、纬度、风速和气压。速度一致性损失为 1.54998314，经过 `1e-3` 权重后贡献约 0.00155；速度监督损失为 4.28436171，贡献约 0.00428。速度类约束仍是总损失的重要组成部分，也说明显式预测速度分量对轨迹建模有实际影响。

惯性损失和科里奥利损失的原始数值很小，但由于权重为 `1e4`，仍能在训练中提供约束。风速-气压损失和近岸衰减损失在最佳轮验证集上分别为 0.00020964 和 0.00821889，说明模型大部分预测不会明显违反强度变化经验，但近岸过程仍存在一定难度。

### 5.3 轨迹可视化

前端将观测轨迹和 PINN 预测轨迹作为主轨迹展示，同时叠加线性平滑基线。如果上传数据包含 `actual_track`，页面还会显示真实轨迹。这样可以直接比较 PINN 与基线在路径弯曲、移动速度、最终位置和强度变化上的差异。轨迹预测不仅需要看单个 loss 数值，地图上的形状、转向和异常跳变同样重要。

## 6. 讨论

### 6.1 物理约束的作用

物理约束在本项目中主要有三点作用。第一，在低维特征和有限样本条件下提供归纳偏置，帮助模型减少不合理轨迹。第二，让输出速度、位置变化和强度变化之间更一致，提升结果的可解释性。第三，为与线性平滑基线对比提供分析角度，观察 PINN 是否能在趋势外推之外学习到更合理的运动形态。

不过，这些约束仍然是弱约束。它们没有引入真实三维大气场，也没有求解完整动力学方程。近岸衰减使用的是简化海岸线函数，科里奥利项也是基于局部速度和加速度的弱残差，因此只能作为物理先验，而不能替代业务级数值天气预报。

### 6.2 数据驱动建模启示

v2 训练结果说明，扩大数据年份后，模型性能和结果可信度都有明显改善。终版数据包含 287 个台风，并按台风编号划分训练/验证/测试集。测试集平均位置误差约 56.45 km，说明模型在未见台风上有一定泛化能力。

同时，数据集仍然是低维最佳路径数据。模型没有看到海温、环境风场、垂直风切变和副热带高压等关键背景场，因此对复杂转向和强度快速变化的解释能力有限。这也说明 AI for Science 中的数据驱动方法需要与更丰富的科学观测和物理变量结合。

### 6.3 局限性

- 输入特征有限：当前模型只使用时间、经度、纬度、风速和气压，没有使用大气环流、海温、湿度、风切变等空间场。
- 预测方式较简单：多步预测采用自回归方式，后续步依赖前一步预测，误差可能随预测步数累积。
- 模型结构较轻量：4 层 MLP 便于训练和部署，但对长时依赖和复杂空间环境的表达能力有限。
- 物理约束较简化：科里奥利和近岸衰减只是弱先验，不能完整描述台风动力学过程。
- 基线实验仍可加强：系统支持 PINN 与线性平滑基线对比，但当前仓库没有保存多案例批量对比表。
